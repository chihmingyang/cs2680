  我讀到的：model 一次出一個 token（中文約一個字）。每出一個 token 都要把全部參數讀一遍，每個參數只算一次，所以比值遠低於門檻、運算電路閒著。把很多請求併成一個 batch，參數讀一遍給整批用，就能分攤搬運。但每個請求還有自己的中間結果，它是從到目前為止的對話算出來的。新 token 要參考前面每一個字，所以每一步都要把這份整份讀一遍。這份分攤不了，所以對話越長，這個請求每一步要讀的越多，它的字出得越慢。

  R9 「每產生一個 token，都要把全部的參數讀一遍」和「每產生一個 token，這份中間結果都要整份讀一遍」：新加的「新的 token 要參考前面的每一個字」說明了每一步「需要用到全部」，但沒說明為什麼「需要用到」就等於「要從記憶體重新讀一次」。上一步才讀過的參數和中間結果，為什麼不能留在做運算的電路上給下一步用？¶1 只說參數放在 GPU 記憶體、要讀到運算電路上，沒說運算電路那一側留不住。我是用自己的知識（運算電路旁邊的儲存空間很小）補上這一步的。
