  我讀到的：per-message effort 的做法是在 messages 尾端插一則只帶 effort 的 system 訊息。它若插在一則新的 user 訊息後面，這一次回應就用新的等級。它若插在別的位置，就從下一則 user 訊息開始生效。只裝 tool 結果的 user 訊息不算。

  R15 「這一輪」：第 3 章 ¶24 把「一輪」定義成 GPU 算出一個 token 的一次計算，還明說「不是 agent 的一步」。這裡的「這一輪」指的是一次回應，或是一個 turn。同一個詞，前後指兩件不同的事，讀者要自己判斷。
  R1／R9 ¶12 的小標是「每一步換 effort」。第 1 章把 step 定義成一個 turn 裡的每一次 model call，第一步以外的 step，送進去的新內容都是 tool 結果。照 ¶13 最後一句，只裝 tool 結果的 user 訊息不算新的 user 訊息。那麼在 turn 中間插 effort 訊息，要等到使用者的下一則訊息才生效。這樣就是每個 turn 換，不是每一步換。這一段和 ¶12 的主張，讀者讀得出兩種結論：一種是在 turn 中間做得到，一種是做不到。文章沒說是哪一種。

  靠：這個單位加前文
  R1 「在那一步的 user 訊息後面加一句」有兩種讀法：一種是把這句接在同一則 user 訊息的文字後面，一種是另外插一則訊息。兩種讀法對 cache 的影響不同，文章沒說是哪一種。
  R2 「那一步的 user 訊息」：一個 turn 裡，第一步以外的 step 沒有使用者寫的訊息，只有裝 tool 結果的 user 訊息（第 1 章、第 5 章 code2）。所以在「每一步」的情境下，讀者指不出「那一步的 user 訊息」是哪一則。¶13 又說 tool 結果的訊息不算 user 訊息，更難判斷。
