  我讀到的：記錯比沒記更糟，因為沒記只是多查幾步、錯看得見，記錯卻照做而且沒有訊息提醒；SWE-ContextBench 讓 agent 解 99 個 issue，直接給配好的舊解法摘要解出 34%（沒有記憶 26%），讓它自己挑只有 36% 挑對、解出 22%，比沒有記憶低 4 個百分點；所以能重讀的不要記，記了的用之前再確認。
  靠：只靠主張、例子對不上
  R16 主張是「記錯，它照著錯的資訊做」（存進去的內容是錯的），接著寫「SWE-ContextBench 量了這件事」。可是實驗裡每一份摘要都是某個舊 issue 的正確解法，錯的是「挑到別題的那份」。例子裡我指不出哪一筆是「記錯的資訊」。

  R9 「拿錯的記憶比沒有更糟」前面少一步：文章只說 36% 的題目挑到配好的那份，沒說其餘 64% 是挑了別份來用，還是什麼都沒挑到。22% 是挑對和沒挑對的題目混在一起的數字，是我自己補上「其餘的拿了別份」才推得出結論。
  R9 「所以……記了的，用之前再確認它還成立」：實驗量的是挑錯份，沒有量「過期、不再成立」。「還成立」這一半前面沒有推出它的那一步。
  R2 「能重讀的不要記」：重讀什麼、從哪裡重讀沒寫。我猜是前面「再查一次」的同一件事，但兩處用字不同。

BLOCK [#tldr ¶3]
  我讀到的：要少記，記的時候帶上「這件事從何時開始成立」和「誰說的」；事實變了就把舊條標上結束月份而不刪，才答得出某個月當時的狀況；來源決定衝突時信誰，例如使用者親口說的不被網頁蓋過；這兩樣要在寫入當下存，之後補不回來。
  靠：我自己的知識
  R1 「時間」有兩種讀法。前面定義成「這件事從什麼時候開始成立，不是哪一天寫下的」，最後一句卻說寫入當下還知道「在什麼時候說的」。「說的時間」是開始成立的時間、還是寫下的時間，我分不出來。
  R2 「原始對話過去之後就補不回來」和 ¶1 接不上：¶1 說 harness 把每個 session 的完整對話原樣存成紀錄（transcript），那誰說的、何時說的，紀錄裡應該還在。這裡的「原始對話」是不是那份紀錄、為什麼補不回來，文章沒說。
  R9 文章沒說為什麼要存「開始成立」的時間、不存「寫下」的時間。¶1 說存時間是為了「分得出哪一條過期」，但這一段處理過期的辦法是另外替舊條標上「到某月為止」。開始時間怎麼幫忙分出過期，是我自己補的（兩條衝突時，開始得晚的那條算數）。
  R16 「5 月時用的是什麼」：例子只有問句，沒有對應的事實。我指不出是誰用什麼、哪一條是舊的、哪一條是新的。拿掉這句，我的重述不變。

BLOCK [#tldr ¶4]
  我讀到的：取回時先用「屬於哪個使用者、專案」（scope）和「現在還成立嗎」（validity）濾掉不該拿的，剩下的再比相似度；只當加分的話，別人的或過期的記憶還是會排進來；這些規則比記憶存在哪裡重要，檔案也做得到，所以建議先用檔案。
  靠：我自己的知識
  R9 文章沒說取回是怎麼做的。「排序的加分」「分數夠高」「排進來」都假設取回是替每一筆記憶算一個分數、排序、取前幾名。這個機制前面沒寫，「分數」是什麼的分數也沒有標籤，是我自己補的。
  R3 「語意相似度」第一次出現，沒有解釋它是誰和誰比、怎麼算。前一句寫的是「用字很像」，用字像和語意像是不是同一件事，文章沒說。
  R16 主張是「檔案也做得到」這些規則，規則的最後一步是「比語意相似度」。括號裡對應的做法是「用 grep 這類搜尋」，grep 比的是字串，不是語意。scope 對得上資料夾，validity 對得上「不再讀進來」，相似度這一項我對不上。
  R9 「比記憶放在哪裡重要：換一個資料庫，規則也不會變」：規則不隨資料庫改變，推不出規則比較重要，中間少一步。而且「資料庫」是第一次出現，前面 store 的例子是「幾個檔案」，沒有人提過要用資料庫，這個對比的另一方我是猜的。
  R7 「這些取回和寫入的規則，比記憶放在哪裡重要」從怎麼取回換到存在哪裡，沒有過渡。

最難讀的三處（即使都過也要列，依難度排）：
1. [#tldr ¶2] 主張講「記錯」，實驗量的是「從正確的摘要裡挑錯份」，再加上「壞的／錯的／拿錯的」幾個名字混用，我對不出實驗證明的是哪一句。
2. [#tldr ¶4] 「排序的加分」「分數夠高」要先知道取回是算分排序才讀得懂；結尾又用 grep 去對「語意相似度」，對不上。
3. [#tldr ¶3] 「開始成立的時間」和「什麼時候說的」像是兩個時間；「原始對話過去就補不回來」又和 ¶1 的完整紀錄互相打架。另外 [#tldr ¶1] 沒有標，但「把 store 裡的每一條和這份紀錄對一遍」讀起來要停一下：前一句是每個 session 各存一份紀錄，「這份」是哪一份沒有指明。
