嚴重度照這次的讀者設定：BLOCK 只留「會讀錯意思／名詞沒交代到那一句讀不下去／例子和主張對不上」。「沒寫為什麼、沒寫怎麼算」和 ¶6 指路裡的名詞不算 BLOCK。下面的 NIT 有幾個在原 checklist 是 BLOCK 級的條目（R2、R3、R12），照這個設定降成 NIT。

BLOCK [#tldr ¶4]
  我讀到的：管 context 有三招，依序是不讓東西進來（測試只交失敗的幾行）、用固定規則刪（重複讀的檔案換成一行占位文字）、請 model 把舊對話濃縮成摘要；三招都不能改 context 的開頭，因為廠商會把開頭存起來，開頭沒變就便宜。
  靠：這個單位加前文；「最前面那一段」是什麼，靠猜
  R2 「context 最前面那一段」指不出來。前文只說 context 裡有讀過的檔案、指令輸出、舊對話，而 ¶1 說「你一開始交代的限制」在開頭、¶2 又說它「夾在一大堆輸出中間」。讀者不知道最前面那一段裝的是什麼、有多長。
  R1 有兩種讀法，而且其中一種和第三招衝突：「舊的對話」是最早進來的東西，照讀者的理解就在最前面；第三招把它換成摘要，下一句卻說三招都不要動最前面。讀者會讀成「第三招本身就違反這條」，或讀成「舊對話不能濃縮」。

NIT [#tldr ¶1]
  我讀到的：請 agent 修 bug，前二十步順利，之後它重讀檔案、漏掉一開始的限制，而且越來越慢越貴，可是你什麼設定都沒改。
  靠：這個單位加前文
  R3 「步」沒說是什麼的一步（agent 做一個動作？問一次 model？）。¶2 的「每一步都要重送」才看得出來，這裡猜得到大意。

NIT [#tldr ¶3]
  我讀到的：agent 表現差時先檢查 harness 怎麼處理 context，再想換 model；有實驗同 model 同題目只改 harness 的做法，解出題數差很多；¶1 的例子該先看那二十步放了什麼進 context。
  靠：這個單位加前文
  R12 「差了 2 倍」有兩種讀法：是另一邊的 2 倍，還是多出 2 倍（3 倍）。也沒說哪一種做法是多的那一邊。
  R2 「context 小到放不下全部內容」：¶2 把 context 定義成那份文字本身，這裡的「小」指的應該是 ¶2 說的長度上限，要讀者自己接。

NIT [#tldr ¶4]
  （同上面 BLOCK 的單位，另一處）
  靠：這個單位加前文
  R2 「算過的開頭」：算什麼沒說，讀者只能讀成「處理過的開頭」。機制留給正文，所以只算 NIT。

NIT [#tldr ¶5]
  我讀到的：工具回傳的文字全部進 context，所以工具要少而專用、回傳要短；出錯訊息要告訴下一步怎麼做；改檔失敗要回報失敗，不能說成功。
  靠：這個單位加前文
  R2 「訊息要寫出下一步該怎麼改」：誰改、改什麼（model 改它下一次的呼叫？人改工具？）指不出來。
  R7 第一句說回傳的字都是 context，下一句接「工具要少而專用」；「少」和 context 的關係沒有過渡（「回傳要短」接得上）。

最難讀的三處（依難度排）：
1. [#tldr ¶4] 「三招都不要動 context 最前面那一段」：不知道最前面是什麼，而且和緊接在前的第三招（濃縮舊對話）看起來互相衝突。
2. [#tldr ¶3] 括號「在 context 小到放不下全部內容的情況下」加「差了 2 倍」：要自己把「context 小」換成「上限小」，倍數也有兩種讀法。
3. [#tldr ¶2] 一個單位裡連續定義 model、harness、context 三個名詞，再接四條因果（越長、越慢越貴、漏看、上限）；每一條都讀得懂，但資訊量是整個區塊最密的。
