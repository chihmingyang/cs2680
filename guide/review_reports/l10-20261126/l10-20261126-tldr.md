BLOCK [#tldr ¶4]
  我讀到的：Model 每產生一個 token 都要把全部參數從 GPU 的記憶體重讀一遍，因為「晶片上的儲存」只有一百多 MB、留不住十幾到上百 GB 的參數，而每個參數只算一次，所以比值遠低於門檻、¶1 那張 H200 的運算能力閒著；把請求併成 batch 可以讓整批共用一次參數的讀取，但每個請求自己那份「中間結果」每個 token 也要整份讀、別人分攤不了，所以對話越長出字越慢。
  靠：這個單位加前文；「晶片」指哪裡是我自己的知識補的
  R15／R3 「晶片上的儲存」第一次出現，沒說是什麼。¶1 只有兩個地方：「GPU 自己的記憶體」和「做運算的電路」。這裡多出第三個地方，又和「GPU 的記憶體」對比，我得自己判斷「晶片」應該就是 ¶1 的「做運算的電路」那一塊、而「GPU 的記憶體」不在這塊晶片上。照字面讀，GPU 本身就是一顆晶片，「晶片上的儲存」和「GPU 的記憶體」會讀成同一個東西，這句就變成自己打自己。
  R17 「它到目前為止的對話算出來的中間結果」、每個 token 都要整份讀、對話越長越大：這是業界叫 KV cache 的東西，審查包沒出現這個名字。
  R18 這一段第一次出現的名詞有四個：token、晶片上的儲存、batch、中間結果；另外帶兩個數字（一百多 MB、十幾到上百 GB）。一段裡還接了三個論點：為什麼逐字輸出慢在搬資料、batch 怎麼分攤、batch 分攤不了的是哪一份。我讀到「但每個請求還有自己的一份資料要讀」時，要回頭重讀前半段，才分得清哪一份是整批共用的、哪一份是各自的。
  R11（NIT）要看出「比值遠低於門檻」差多遠，我回頭對了 ¶3 的「每 byte 206 次」和 ¶1 的「0.5%」，自己算 1 ÷ 206 ≈ 0.5%，才猜這三處說的是同一件事。這裡的單位是「每個參數算一次」，¶3 的單位是「每 byte 幾次」，一個參數幾 byte 沒寫，我對不準。
