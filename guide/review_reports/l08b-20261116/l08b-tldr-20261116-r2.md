## 第一輪三個 BLOCK 的狀態

- ¶2，harness 一下是三樣東西之一、一下是整體：**已解決**。¶1 把 harness 定義成「包在 model 外面、替它執行動作的那一層程式」。¶2 把整體叫「跑 agent 的系統」，把 harness 列成三塊元件之一，兩個名字分開了。還有一點殘留，降成 NIT，見 ¶2 和 ¶6：頁首標題「Harness Architecture」和 ¶6 的「八個開源 harness」，讀起來又像是整個系統。
- ¶3，「除錯更難」方向相反、container 和程式是不是同一件事：**已解決**。現在的寫法是：函式呼叫「分不出是哪一個壞了」，對上 ¶1 的「分不出是 harness 有 bug 還是 container 死了」；協定的代價是「要到好幾個服務找 log」，那是另一種除錯成本，和例子不衝突。「同一個 container 的同一個程式裡」說出了兩層的包含關係。¶1 說 container 是「把程式和它要用的檔案包在一起」的環境，所以接得上。還有一點殘留，降成 NIT，見 ¶3：sandbox 在 ¶1 叫「隔離環境」，¶3 卻說同一個程式裡沒有隔離。
- ¶5，「多個 agent 要共用」和「不看 agent 有幾個」衝突、筆電例子和網頁騙憑證衝突：**兩個衝突都已解決**。¶4 改成「agent 有幾個只是其中一題」，和 ¶5 的第三題一致。筆電例子加了「不讀外部網頁也不碰秘密」，不再和 ¶1 衝突。但同一個例子現在有一個新問題：它沒對上第二題，見下面的 BLOCK。
