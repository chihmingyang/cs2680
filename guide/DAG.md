# 觀念 DAG：規則

更新紀錄在 `guide/CHANGELOG.md`。

頁面：https://chihmingyang.github.io/cs2680/dag.html （2026-11-08 起，草稿，首頁還沒連過去）
資料：`docs/dag.json`。頁面由 `python3 -I tools/dag.py` 產生，改資料就重跑；`--check` 只檢查，`verify.sh` 會跑。

## 為什麼要有這張圖

James 2026-11-08 提出：課程現在用一小時的 slides 切成一堂一堂，沒有對到真正的概念理解；他要一張觀念的 DAG，每個觀念是某個觀念的延伸，分基礎、進階、專家三級，之後把整個課程改成 DAG 的形式進行。這張圖是第一步：先把現有 11 堂的核心觀念拆成節點、畫出「要先懂」的邊，算出講次和觀念對不上的地方，再談怎麼重新分堂。

## 節點

- 一個節點是一個觀念：能用一句話寫成主張（`name`），有自己的前置，刪掉它後面某個觀念就讀不懂。
- 起點是各堂核心觀念的章（v7 版面已經一章一個想法）。一章講兩個前置不同的觀念就拆成兩個節點（`src` 寫到小節，例如 `l01#i9-1`、`l01#i9-3`）；兩堂講同一個觀念就併成一個節點（`src` 列兩堂，講得最完整的那一堂放第一個，頁面上方塊的 L 數字用它）。
- 目錄章（查閱用的清單）不是觀念，列在 `excluded`，不進圖。
- 欄位：`id`（英文 slug）、`name`（一句話主張，可以直接用章名）、`short`（方塊上的短名，中文字寬 11 以內，超過會 warn）、`tier`、`theme`（泳道）、`src`、`deps`、`why`。
- `why` 寫「從 X 與 Y 延伸：…」，要說出少了前置哪裡讀不懂。這一句是點開節點時讀者看到的主文，也是檢查邊有沒有畫對的方法：寫不出來就是邊畫錯了。

## 邊

- `deps` 裡的 A 對這個節點 B 的意思是「讀 B 之前要先懂 A」。方向是前置 → 延伸。
- 只畫直接的前置。A → C 能從 A → B → C 推出來就不畫；`--check` 會把這種多餘的邊列成 warn，2026-11-08 已全部拿掉（從 194 條減到 164 條）。
- 邊只看觀念，不看講次。前置在後面的講次是正常的，那正是要找的落差。

## 難度

| 難度 | 標準 |
|---|---|
| 基礎 | 一句話能說清楚；靠日常經驗或一個前置觀念就能懂；不懂它，後面多數觀念讀不下去 |
| 進階 | 要同時拿著兩個以上的前置觀念才能懂；通常是在做一個設計決定，或算一次帳 |
| 專家 | 要進到機制內部（算式、硬體單元、演算法），或要能判斷研究結論的效度；不自己做 serving、harness、評估的人可以跳過，不影響上游的判斷 |

- 難度是觀念本身的性質，不是圖上的深度。「分散式狀態」在第 2 層但是專家；「先用檔案」在第 7 層但是進階。
- 一條硬規則：前置的難度不能比這個觀念高（基礎 ≤ 進階 ≤ 專家）。違反就是邊畫錯或難度標錯，`--check` 會擋。

## 版面

- x 是依賴深度：從起點算最長路徑的長度。第 k 層的前置都在前 k 層，所以由左到右就是一個合法的閱讀順序（拓樸排序）。
- y 是主題泳道（`themes` 的順序）。同一格有好幾個觀念時上下排，依前置的位置排序。
- 顏色是難度：基礎 `--dg-a`、進階 `--dg-c`、專家 `--dg-d`，方塊左緣的灰條也跟著難度變深。
- hover／點一個觀念：前置用藍實線往左亮，延伸用橘虛線往右亮，其他淡掉；下方面板顯示主張、`why`、出處、前置、延伸出去的觀念。清單裡的觀念名也都可以點。
- 篩選：難度勾選、講次下拉（看一堂的章散在圖的哪裡）。「縮到螢幕寬」把 1178px 的圖縮進內容欄。
- 這一頁沒有側欄：圖要 1178px 寬，有側欄的內容欄只有 920px。topbar 的連結不要加 `rel`，手機版的 CSS 會把 `.lecnav a[rel]` 畫成圓形箭頭鈕。

## 頁面下半（從資料算出來）

- **一個觀念散在兩堂**：`src` 跨兩堂的節點。
- **前置觀念在後面的講次**：節點被教的那一堂（`src[0]`）之前，前置連帶過都沒出現過（前置的 `src` 裡最早的講次 > 節點的主要講次）。前置若在更早的講次提過一句就不算，所以這個數字比「主要講次比較」小很多（7 條對 17 條）。
- **每一堂的難度組成與深度範圍**：節點算在 `src[0]` 那一堂。
- **依賴順序的閱讀清單**：一層一組，層內依主題。是改成 DAG 形式時的順序草稿，不是分堂。

## 怎麼改

1. 改 `docs/dag.json`。新講次：每章一個節點（或拆、併），`src` 對到 `docs/lXX.html` 的章 id；目錄章加進 `excluded`。
2. `python3 -I tools/dag.py --check`，看 ERROR 和 warn。
3. `python3 -I tools/dag.py` 重寫 `docs/dag.html`，截圖看一次（圖、點一個節點、手機版）。
4. 章 id 改了（`add_anchors.py` 重編）會被覆蓋檢查抓到：每一章都要被某個節點蓋到或在 `excluded`。

## 2026-11-08 第一版的判斷（James 還沒確認）

- 粒度選章不選小節：100 個節點、164 條邊、8 層。小節約 300 個，圖會讀不了；要再細，先在某一個主題試。
- 四個起點：Agent loop、機率性輸出、Prefill 與 decode、GPU 換 throughput。其他 96 個都從這四個延伸。
- 難度分布：基礎 19、進階 69、專家 12。進階偏多，是因為多數章本來就是「做一個決定」；要不要把其中一部分降成基礎（例如 Batching、Prefix cache）或升成專家，看他。
- 幾條有爭議的邊：「分數是系統的輸出」（L7）是「先查 harness」（L4）的前置；「驗證迴圈」（L6）是「能驗證才能放手」（L3）的前置；「三個數字」（L9）是「P/D 分離」（L1）的前置。這三條都是前置在後面的講次，也是重新分堂時最該先動的地方。
