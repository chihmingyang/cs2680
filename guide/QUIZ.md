# 題庫：每一節的小測與整合題

替一堂建題庫的操作步驟在 `.claude/skills/build-quiz/SKILL.md`（2026-11-09）；這份是規則與 L6 的結果。

2026-11-08 起。L6 整堂都有（第 1–4 章是 pilot，同一天擴到第 5–10 章：42 節、97 題 unit、7 題整合；2026-11-09 補齊觀念涵蓋：320 個觀念、258 題 unit，見〈觀念涵蓋〉）。同一批題有兩個用途：讀者讀完一節就做那一節的題；CI 的第 2 層（`WORKFLOW.md` J）拿它當 regression test。兩者衝突時讀者自測優先（2026-11-11 James，見〈讀者自測優先〉）。

題型（2026-11-08 James 要求：自己要能快速知道答對沒有）：

- **選擇題**（`kind: choice`）：回想題都用選擇題。點選項立刻判對錯；選錯，那個選項下面寫它錯在哪，可以再選；選對，鎖住並顯示解說。記的是這次第一次選的結果。
- **問答題**：應用題（`kind: apply`，換數字、換情境）和整合題。寫下答案、看答案要點、自己按「都答到／有漏」。它們要測的是自己推得出來、兩節接得起來，給了選項就能從選項反推，所以不做成選擇題。

## 為什麼這樣切

James 2026-11-07 提出：一章一題太少，基本觀念一題、重要觀念幾題。把內容拆成一節一節有連貫性的 knowledge section，學完一節就做那一節的題（unit test），讀完幾章再做把幾節合起來用的題（integration test）。

這樣切的價值在診斷：

| 結果 | 代表什麼 | 怎麼做 |
|---|---|---|
| unit 題錯 | 那一節沒教好，或被改壞了 | 改那一節 |
| unit 題都對、整合題錯 | 每一節都教了，但節和節之間怎麼接沒寫出來（2026-10-19 James 說的「卡」） | 補承接句，或在後一節點出它接的是哪一節 |
| 都對，James 還是說看不懂 | 題庫缺了這一題 | 補一題，像修完 bug 補一個 test |

## 讀者自測優先：問含義，不問數字（2026-11-11）

James 讀 L6 的題目時發現有些題在問論文的數字，問：這對掌握原理的幫助多大？數字背後的含義是不是才最重要？答案是後者，而且他定了優先順序：讀者自測比 regression test 重要。

**判準是遷移。** 讀者離開這篇文章、去設計自己的 agent 時，答對這題會不會讓他做出不同的決定？會才出題。「把題幹的論文名和數字拿掉，還問得出東西嗎」不夠準：ImpossibleBench 的 Oneoff 和 Conflicting 差在哪，拿掉論文名還是問得出來，但答對了也不會改變任何設計。

帶數字的題分三種：

| 種類 | 例子 | 怎麼做 |
|---|---|---|
| 數字是機制算出來的 | 用 pⁿ 算 30 步、每步 97% 的全對率（k1b） | 留，放應用題。這是在測機制 |
| 數字是量測的方向和量級，而且推翻直覺 | 救不回來之後很快停下的不到兩成（k12c） | 留，但選項要寫含義（「大多不停」），不能只有數字；題幹先問問題，論文名和日期放解說 |
| 精確值、benchmark 怎麼設計、出處與證據力 | 26% 還是 66%；Oneoff 的定義；這是誰的判斷 | 不出題。觀念清單標 `evidence` |

**源頭在觀念清單。** 題目照 `points` 出，清單怎麼寫，題目就怎麼問：

- 量測類的觀念寫成「發現 → 所以怎麼設計」。L6 的 k12.1 寫了「agent 很少自己停…所以上限要從外面加」，題目就問到含義；舊的 k5.2 把「26% 的失敗 run 宣稱自己成功」並排放在句尾，題目就只考了 26%。
- 數字本身另列一條 `evidence`。它是那條觀念的證據，不是觀念。
- `evidence` 不強制出題（`check` 放行），改由 `check_numbers.py` 保護（見〈數字對照〉）。一題的 `covers` 只有 `evidence`，`check` 會擋。
- 選項只有數字的選擇題，`check` 會 warn。每個錯的數字各對應一種算錯的方式時可以留（L5 的 k2e：15 是和聊天比、11 是相減），在題目加 `"num_choices_ok": "理由"`。

**這和閉卷那一關的關係。** 閉卷規則原本寫「選擇題問文章量到什麼」，又要求閉卷答不出來。照這個方向走到底，剩下的只會是任意的事實，因為懂原理的人本來就推得出原理題。所以：閉卷只抓線索（最長、不合理的選項、互相洩漏、題幹給齊數字）；因為懂而答對的題是好題，標 `closed_ok`。「文章有沒有寫」靠開卷那一關。

**代價。** `evidence` 不出題之後，沒有數字的那幾條（例如「這張時間軸是幾個量拼成的」「這是本文的判斷，不是量測」）沒有任何檢查保護；被刪掉不會轉紅。目前接受：這類內容該由可讀性審查和來源檔管，不該靠讀者的小測。

**L6 照這個改的結果（2026-11-11）：** 刪 4 題（k5g、k6d、k2e、k11h）；5 題改成問含義（k5c、k5b、k5f、k5i、k10c）；8 題的題幹把論文名移到解說（k2a、k2b、k2d、k6b、k9a、k12c、k12d、k14f）；觀念清單 4 條改標 `evidence`、新增 9 條放數字、5 條改寫成「發現 → 所以」。106 題變 102 題。L6b、L5、L7 還沒照這個掃過。

## 資料放在哪裡

- 題庫在頁面裡：`</main>` 之後、`<script src="app.js">` 之前的 `<script type="application/json" id="quiz">`。頁面就是唯一來源，不另開檔案。
- 審查包（`review_pack.py`）和 `page_text.py` 都會去掉 `<script>`，所以作答的 agent 讀不到答案。
- `app.js` 讀它，在每一節的最後放一個收合的「小測」，在 `scope` 最後一章的最後放「整合題」。讀者寫的答案和「都答到／有漏」只存在自己的瀏覽器（localStorage `cs2680.quiz.<lXX>.<題號>.a`、`.v`）。
- 左邊目錄跟著打勾（2026-11-10，James：要快速看出還沒讀的範圍）：一節的 unit 題都有作答紀錄（`.v` 是 ok 或 miss，對錯都算），目錄裡那一列加 ✓；做了一部分在同一欄顯示外框小標「做了/總題數 題」（只寫數字像日期，2026-11-10 James）；標記都靠右對齊成一欄；章那一列加總它所有的節。目錄列對到「起點在它之前的最後一節」，所以併進章首的小節（L6 3-1）和章首同一個標記；章首那一節本身沒有獨立的列，看章那一列。整合題不算。`app.js` 產生，不寫進 HTML。
- 一堂拆成兩堂時（2026-11-10，L6 → L6／L6b），搬走的節與題保留原 id，新頁的 JSON 加 `"moved_from": "l06"`：`app.js` 第一次打開新頁時，把 `cs2680.quiz.l06.<題號>.*` 複製成 `cs2680.quiz.l06b.<題號>.*`，讀者在舊頁做過的題不會不見。新開的節用沒用過的 id（L6 的 `k43`），不重用搬走的 id。
- `edit.js` 不讓 `.ks-quiz` 進入編輯；小測是 JS 產生的，網頁編輯存檔也不會把它寫進 HTML。

格式（L6 的節錄）：

```json
{
  "version": 1,
  "scope": ["i1", "i2", "i3", "i4"],
  "sections": [
    {"id": "k1", "from": "i1",   "title": "錯誤相乘：pⁿ", "core": true,
     "points": [{"id": "k1.1", "type": "claim", "t": "run 全對的機率是 pⁿ…", "at": ["#i1 ¶1"]}]},
    {"id": "k2", "from": "i1-1", "title": "算式的兩個前提", "points": […]}
  ],
  "unit": [
    {"id": "k1a", "ks": "k1", "kind": "choice", "q": "題目",
     "choices": [{"t": "錯的選項", "why": "錯在哪"}, {"t": "對的選項", "ok": true}],
     "key": ["答對後顯示的解說"], "covers": ["k1.1"]},
    {"id": "k1b", "ks": "k1", "kind": "apply",  "q": "換數字的題目", "key": ["…"], "covers": ["k1.5"]}
  ],
  "integration": [
    {"id": "x1", "ks": ["k1", "k4", "k8"], "q": "題目", "key": ["…"], "after": "i4"}
  ]
}
```

- **節＝文章自己的小節。** 章首（從 `#iN` 到第一個小節）是一節，每個帶 id 的小節（`p#iN-M`，粗體 lead-in 那一段）各是一節。`from` 是起點的 id，一節到下一節的起點為止。不在 HTML 加新標記。
- 章首只有一句過場時（例如 L6 第 3 章），它和第一個小節併成一節：`from` 寫章的 id，不寫第一個小節的 id。
- `scope` 列出題庫涵蓋的章。每一章的開頭都要屬於某一節。
- 整合題的 `after` 是放在哪一章的最後（預設是 scope 的最後一章）。同一個位置的整合題放成一組，標題的「第 a–b 章」由這一組用到的節算出來。`after` 之後的節不能用：讀者做題時還沒讀到（`check` 會擋）。舊 L6 放兩組：第 4 章後（可靠性）、第 9 章後（記憶，含一題接回第 2、4 章）；2026-11-10 拆成兩堂後，L6 的整合題在第 4 章後，L6b 的在第 5 章後，接回可靠性的那一題（x7）改成只用 L6b 的節，L6 的觀念寫在題幹裡當前提。目錄章不放整合題。

## 出題規則

- **選擇題要通過閉卷測試**（2026-11-08 加）。同一批題不給文章，讓 agent 作答（`quiz.py closed`／`closedcheck`）；閉卷也答對、而且有把握的題，就是沒在測文章。L6 第一次閉卷：87 題答對 85、有把握 80（猜的期望值約 29）。原因有四種，寫題時避開：
  - **正確選項最長、最具體**：87 題有 67 題正確選項最長，平均是錯誤選項的 2.6 倍。正確和錯誤選項要一樣長、一樣具體、同樣的句型。
  - **錯的選項不合理**：「太絕對」「離題」「違反因果」（舊 k6a 把 lock-in 排在出錯之前）一眼就能刪。錯的選項要邏輯上說得通，最好是文章要破除的那個直覺（新 k6a：以為看到症狀時還來得及救）。
  - **題目互相洩漏**：k2c 的題幹說「兩個前提都不成立」，k2a、k2b 就不用讀；k20b 的選項寫了「記錯比沒記代價高」，等於 k18a 的答案。題幹和選項不能寫出別題的答案。
  - **題目給齊了全部輸入**：0.95⁵⁰ 這類題，題幹給了數字，會算就答得出來，不需要文章。計算放應用題；選擇題問文章主張什麼、量測的結果代表什麼，尤其是常識和文章結論相反的地方。不問精確值和出處（2026-11-11，見〈讀者自測優先〉）。
- 閉卷答得出來的原因有兩類，處理不同。**線索**（最長、不合理的選項、互相洩漏、題幹給齊數字）一定要改。**常識或推理**（冪等、Claude Code 的行為、從題幹的因果推得出）可以留：再改下去只會變成考冷門細節；留的題在資料標 `"closed_ok": "理由"`，`closedcheck` 會分開列，不算要改的。
- **閉卷這一關只抓線索，不要求答不出來**（2026-11-09，補觀念涵蓋時改）。作答的 LLM 背景知識遠比讀者強：新寫的 203 題選擇題閉卷答對 202 題、有把握 179 題，大多是因為觀念本身就是這個領域的常識。所以閉卷答對的題，另開一個 agent 依題目和閉卷理由分成五類（compute／leak／option／knowledge／reasoning），線索三類照規則改，改完再閉卷一次；常識、推理和只在別節出現的洩漏標 `closed_ok`。測「文章有沒有寫」靠開卷那一關：作答者只能用文章、要引用該節，文章沒寫就選「文章沒寫」（見下面〈觀念涵蓋〉的 mutation 結果）。
- **同一節的題目會一起出現，不能互相給答案。** 一節六、七題時最常見的毛病是洩漏：前一題的題幹或選項寫出後一題的答案。兩題其實在考同一件事時，不要只改措辭：後一題換成應用題、給新情境，或兩題併成一題（`covers` 合併）。
- 作答包和閉卷包裡的選項，用題號當種子打亂（`quiz.py` 的 `shown()`），和頁面一樣不照資料的順序；同一題每次順序相同，評分才對得回字母。
- 重點觀念至少 4 題，其中至少 2 題選擇、1 題應用（2026-11-08 起；計算移到應用題之後，從「3 選擇＋1 應用」放寬）。
- **第 2 章重寫的結果（2026-11-08）**：舊版 8 題選擇題閉卷全部有把握答對；新版 9 題選擇題，閉卷有把握答對 4 題，都是常識或推理（標了 `closed_ok`），另外 5 題閉卷只能猜（k5c 還猜錯）。開卷 9 題全對，應用題 k4e 評分全過。作答者指出 k7b 的正確選項照抄程式碼註解、比對字面就會對，改成問「不檢查會發生什麼」。
- 閉卷的作答者是 LLM，推理和背景知識都比剛入門的讀者強，所以閉卷答對不一定代表人也猜得到；但「正確選項最長」「錯的選項不合理」這兩種線索，對人一樣有效。
- 回想題寫成選擇題，**預設 3 個選項**（1 個正確、2 個錯的），剛好一個正確。只有寫得出 3 種真的誤解時才用 4 個，例如數字題的每個錯數字各對應一種算錯的方式（k4b：88% 是以為漏一點沒差、70% 是打八折、28% 是和另一列搞混）。不寫湊數的選項：沒人會選的選項只是多讀一行（Rodriguez 2005 整理 80 年研究，3 個選項最好；`quiz.py check` 擋 5 個以上）。2026-11-08 刪掉 k1a、k4a 的「約 50%」，它沒有對應任何誤解。錯的選項要是讀者真的會有的誤解（例如把「看到症狀」當成「出錯的時間」、把 epistemic 當成換 model 能補的那一類），每個都寫 `why`：選它時要告訴讀者錯在哪。不要寫一看就錯的湊數選項。頁面每次載入會打亂選項順序，所以資料裡正確選項的位置不用平均。
- 一題問了幾件事的回想題，拆成幾題選擇題，一題一件事。
- **重點觀念多出幾題。** 在 `sections` 標 `"core": true`（本章的主要主張；L6 第 1–4 章是 K1 錯誤相乘、K4 檢查加重試、K8 切幾段、K14 定位；第 5–9 章是 5-1、6-1、7-1、8-4、9-2），至少 4 題，其中至少 2 題選擇、1 題應用（`check` 會擋）。幾題要從不同角度問同一個觀念：數字、反過來算、因果、常見的誤解。不要同一題換句話說，那樣記住第一題的答案就全對，測不到懂不懂。用猜的三分之一會中，但同一個觀念三題都猜中就不太可能，所以防猜靠多出幾題，不靠多加選項。整合題在讀完幾章後再問一次這些觀念，等於隔一段時間再考一次。頁面上重點觀念的小測標題有「重點」標籤。
- 每一節至少一題 unit。重要觀念 2–3 題，其中至少一題 `apply`：換數字或換情境，文章裡沒有現成的答案，只能用那一節講的機制推出來。只問文章寫過的句子，人和 agent 都能「找到那句」就答對，不代表懂。
- `key` 一個要點一句，數字寫出來。評分照要點逐條判斷，所以每個要點要能單獨判斷對錯。「任選兩種」這類寫成一個要點，並列出全部可以接受的答案。
- 整合題至少用到兩節，問的是節和節之間的接點。例如 L6 的 x1：第 2 章說每步檢查、第 3 章說每 10 步驗證一次最省，兩者怎麼並存。
- 題目從現在的文字出。這是 snapshot test：抓「原本教了、後來被改壞」。抓「本來就沒教到」是審查者和 James 讀頁面的工作，不混在一起。
- 數字用程式算過再寫。
- **要點只寫文章寫了的東西。** Pilot 的 k14b 要點寫了「截斷時保留錯誤行與 exit code」，文章沒寫這個修法（只指到 L4），兩個評分者一個給分、一個不給，成了唯一不一致的題。
- **不要求題目沒問的東西。** Pilot 的 k1b 只問數字，要點卻要作答者複述前提，兩次都因此不過。
- **標題或 tldr 也寫了的數字，刪掉內文它還是會過。** 要測一節的機制，就出 `apply` 題（見下面的 mutation 結果）。
- 改了小節的 id 或刪了小節，`quiz.py check` 會報錯（`verify.sh` 會跑）。改了某一節的內容，對應題目的 `key` 也要跟著改。

## 觀念涵蓋（coverage）

James 2026-11-09：「不是補到兩題的問題，是有些考題可能過少，就像 unit test 只測試 happy case。」題數夠不代表測得完整，要先有一份「這一節教了哪些觀念」的清單，才知道哪些沒測到。

- **Spec：每一節的 `points`。** 一個觀念一條：`id`（`k4.3`）、`type`、`t`（一句話）、`at`（出處的定位，給人找原文用，改文章後可能過時，`check` 不檢查它）。`type` 六種：claim（主張）、mechanism（機制）、condition（前提：要先成立什麼）、limit（限制、例外、代價）、misconception（文章要破除的誤解）、evidence（2026-11-11 加：量測的精確值、benchmark 怎麼設計、出處與證據力；不出題，見〈讀者自測優先〉）。condition、limit、misconception 就是 edge case。
- **每題標 `covers`**：它測到哪幾個觀念，只能是自己這一節的。「答對這題必須懂那個觀念」才算，順帶提到的不算。
- **`quiz.py check` 擋三件事**：`evidence` 以外的觀念沒有任何一題 unit 測到；`covers` 指到別節或不存在的觀念；一題的 `covers` 只有 `evidence`。`quiz.py coverage` 列出每個觀念被哪幾題測到。
- **清單由沒看過題目的 agent 寫**，只拿讀者看得到的文字（不含收合的本文延伸、第 10 章的名詞註），不然會照著現有的題目列，等於拿 test 當 spec。
- **改了某一節的內容**：先改它的 `points`（多教了一件事就加一條，刪掉的就拿掉），`check` 會指出哪一條沒有題目。
- **新講次的題庫**：先寫 `points`，再出題，不要先出題再補清單。

## 數字對照：`check_numbers.py`（2026-11-11）

題目不再考精確值之後，數字改由程式保護。內容是 agent 改寫的，改寫時把 54% 寫成 45%、或補一個來源沒有的數字，句子讀起來一樣順，讀者和可讀性審查都看不出來。`guide/sources/lXX.md` 已經逐條記了原文的數字，所以拿它對。

```bash
python3 -I tools/check_numbers.py docs/l06.html        # verify.sh 會跑
python3 -I tools/check_numbers.py docs/l06.html -v     # 另外列出每個來源被哪幾段引用
```

- 來源檔的一筆＝一個頂層「- 」項目和它縮排的幾行；裡面的網址是 key，裡面的數字是可以出現的數字。
- 頁面的一段寫出了某個來源（有連到那個網址的連結，或寫出它的名字，例如 Failure as a Process），從那一句起到這一段結束，每個數字都要在那一筆裡找得到。四捨五入算對得上。
- 對不上有三種處理：數字錯了就改頁面；來源檔漏記就重開原文核對，再補進那一筆；這個數字是本文自己算的（100% − 71% = 29%），或出自同一段沒寫名字的另一個來源，就在那個元素加 `data-num-own="29"`。
- `evidence` 類的觀念：每個數字要在來源檔裡，也要還在它那一章的讀者文字裡（百分比連 % 一起比）。正文把那個數字刪掉或改掉，這裡會轉紅。
- 題目的題幹、正確選項、答案要點寫了來源的名字時，裡面的數字要在來源檔裡；本文自己的數字加 `"num_own": "29"`。
- 清過的講次在來源檔加 `<!-- check_numbers: strict -->`，對不上就讓 `verify.sh` 失敗。現在是 L6、L6b。其他講次只印一行 note：各堂來源檔的寫法不一樣（有的不是一筆一個網址），列出來的多半是格式對不上。要清一堂，先把它的來源檔整理成一筆一個來源。

## 怎麼跑（CI 第 2 層，現在手動）

```bash
python3 -I tools/quiz.py exam docs/l06.html > notes/quiz/exam.md        # 作答包：讀者文字＋題目，沒有答案
# 開一個新的 subagent：只讀 exam.md，照它的規則作答，寫 notes/quiz/ans.json
python3 -I tools/quiz.py grade docs/l06.html notes/quiz/ans.json > notes/quiz/judge.md
# 再開一個新的 subagent：只讀 judge.md，寫 notes/quiz/verdicts.json（每個要點 1 或 0）
python3 -I tools/quiz.py report docs/l06.html notes/quiz/ans.json notes/quiz/verdicts.json
```

- **一題「過」＝兩個條件都成立。** 內容對：選擇題由程式比對選項；問答題由評分 agent 判斷每個要點都答到，而且作答者引用的文字真的寫了。定位對（程式判斷）：unit 題至少一個定位在它那一節，整合題在它列的每一節各至少一個。
- 作答包裡每題選擇題最後都多一個「文章沒寫，答不出來」，作答規則要求文字找不到支持就選它。沒有這個選項，作答的 agent 會用自己的知識選對，刪掉內容後題目也不會轉紅。頁面上給人做的不加這個選項。
- 定位的規則是把「你知道不算，文章寫了才算」變成機械檢查。第 1 章圖 4 也寫了「88%」，但 K4 的題要引用 K4 那一節，才算 K4 教到了。
- 作答和評分用兩個不同的 agent，都沒看過寫作過程，評分的也沒看過作答的推理。
- 只跑受影響的題：改了某一節，跑那一節的題、以它為前置的節的題、含它的整合題。Pilot 先全跑。
- `report` 給兩組以上的 answers／verdicts，就會列出各次結果不一致的題（雜訊）。

## Pilot 結果（2026-11-08，L6 第 1–4 章）

**基準：目前的頁面，作答＋評分各兩次。** 第一次跑，unit 20/22 與 21/22，整合 3/3 與 3/3。沒過的 k1b、k14b 都是題目出錯，不是文章的問題（見上面出題規則的最後三條）。改了 key 之後，k1b 兩次重評都過，k14b 的新題目重新作答一次也過：25 題在目前的頁面上全過。

**雜訊：** 25 題裡兩次結果不一致的只有 k14b，原因是它的要點文章沒寫。可讀性審查同一包審三次，BLOCK 數晃 ±2（`REVIEW_READABILITY.md`〈審查者的雜訊〉）；題庫是一題一題判過不過，穩得多，可以當 gate 的候選。

**Mutation test：** 在副本刪掉 K4 的算式（code1）、四種情況的表（表1）和「8% 升到 88%」那一段，重新作答、評分。

| 題 | 結果 | 誰抓到的 |
|---|---|---|
| k4b（漏兩成、重試一半會錯） | 轉紅 | 評分：作答者說算式沒寫，算不出 55%、28% |
| k4c（換數字算 s） | 轉紅 | 評分：沒有 s 的算式，0.99 與 61% 答不出 |
| x1（第 2、3 章怎麼並存） | 轉紅 | 程式：每個要點都答到，但沒有一個定位落在 K4 |
| k4a（8% 變 88%） | 仍然過 | 第 2 章標題還寫著「8% 也能變 88%」，作答者用 pⁿ 反推出一步約 99.7% |
| 其他 21 題 | 不受影響 | — |

刪掉的是算式：考算式的題全紅，只考標題數字的 k4a 留綠，這個結果是對的。x1 證明定位檢查有用：只看答案內容，它會是綠的。

**選擇題版（同一天，30 題選擇題）：** 只出選擇題，基準與刪 K4 算式的副本各作答一次，程式評分。

- 基準 30/30 過，作答者沒有選「文章沒寫」。
- 副本：k4b（漏兩成）、k4d（重試一半會錯）轉紅，作答者都選了「文章沒寫」，因為算式不見了；k4a 仍然過，理由和問答版一樣（標題還寫著 8% 變 88%）；其他 27 題不受影響。
- 選擇題只要作答、不用評分：一次約 8 萬 token、不到 1 分鐘，問答版是作答＋評分約 21 萬 token。
- 結論：加了「文章沒寫」選項、再加定位檢查，選擇題刪掉內容後一樣會轉紅，而且便宜很多。CI 先跑選擇題；問答題留給應用與整合。

**第 5–10 章（同一天，62 題新題）：** 盲讀作答一次，52 題選擇題全對，引用都落在該節。作答者另外指出 3 題本身有問題（k23d 問的月份兩個答案都對、k18d 的例子其實會報錯、k38b 的選項說得比文章多），修了再作答，第二位作答者又指出 k23d 分不出懂不懂（答案剛好等於現在的值）、要點要求文章沒寫的做法。改到第三版，10 題問答題評分全過。

教訓：**作答的 agent 最會抓爛題。** 它只讀文章，所以題目要求文章沒寫的、兩個選項都對、題目說得比文章多，它都會卡住。作答規則第 5 條因此要它把題目的問題寫在 `"_issues"`。新題第一次跑，先看 `_issues` 再看分數。

另外抓到一處文章本身的不一致：第 5 章說指令能重讀就不要記，第 8 章的 memory_eval.yaml 卻有一條 should_recall 是 "how do we run tests"。（待 James 決定要不要改。）

**成本：** 作答一次約 10–11 萬 token、3–5 分鐘；評分一次約 10 萬 token、1.5–2 分鐘（評分包會重複列出引用的文字）。全跑一次約 21 萬 token。只出幾題時，作答包還是要整頁的文字，一次約 7–9 萬 token。所以 CI 只跑受影響的題，而且先手動跑，要不要接進 Actions 等 James 決定。
