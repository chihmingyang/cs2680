## 自己做 eval
- ✔ Anthropic, Demystifying evals for AI agents. Mikaela Grace, Jeremy Hadfield, Rodrigo Olivares, Jiri De Jonghe. 2026-01-09. https://anthropic.com/engineering/demystifying-evals-for-ai-agents
  - "20-50 simple tasks drawn from real failures is a great start"
  - 定義 task, trial, grader, transcript, outcome, evaluation harness, agent harness, evaluation suite
  - capability evals：start at a low pass rate；regression evals："should have a nearly 100% pass rate"；可 graduate
  - "two domain experts would independently reach the same pass/fail verdict"
  - "a 0% pass rate across many trials (i.e. 0% pass@100) is most often a signal of a broken task, not an incapable agent"
  - "One-sided evals create one-sided optimization."
  - "it's often better to grade what the agent produced, not the path it took"
  - Opus 4.5 "initially scored 42% on CORE-Bench"，"After fixing bugs and using a less constrained scaffold, Opus 4.5's score jumped to 95%."；嚴格評分把 96.12 判錯（期待 96.124991…）
  - internal evals: Claude gained "an unfair advantage" by examining git history from previous trials
  - 表：automated evals / production monitoring / A/B / user feedback / manual transcript review / systematic human studies；Swiss Cheese Model
  - "teams without evals face weeks of testing while competitors with evals can quickly determine the model's strengths, tune their prompts, and upgrade in days"
- ✔ Hamel Husain & Shreya Shankar, evals FAQ. https://hamel.dev/blog/posts/evals-faq/why-is-error-analysis-so-important-in-llm-evals-and-how-is-it-performed.html （2025-06-27，改 2026-09-01）；https://hamel.dev/blog/posts/evals-faq/whats-a-minimum-viable-evaluation-setup.html （2025-06-29，改 2026-05-04）
  - error analysis 是 "the most important activity in evals"；open coding → axial coding（failure taxonomy，數每一類）；先自己標至少 30 條 trace；focus on "first failure"；約 100 條 diverse traces 的工作池；theoretical saturation；"benevolent dictator"；"counter-productive generic metrics"；"30 minutes manually reviewing 20-50 LLM outputs"
- ✔ LangChain, State of Agent Engineering. 調查 2025-11-18 到 12-02，1,340 份，報告 2026-06-12. https://langchain.com/state-of-agent-engineering
  - offline 52.4%、online 37.3%、observability 89%、production 57.3%、人工 59.8%、LLM judge 53.3%、32% 把 quality 列為最大障礙
- ✔ LangChain, The Most Common Questions About Agent Evals. Divya Santhanam, 2026-10-15. https://www.langchain.com/blog/common-questions-about-agent-evals
  - "Failures that online evals flag become new examples in your offline dataset."；10 到 20 個真實 trace 起步；online 通常沒有 reference outputs；multi-turn 看整條 thread
- ✔ Cursor, CursorBench. Naman Jain, 2026-03-11. https://cursor.com/blog/cursorbench
  - "our internal eval suite based on real Cursor sessions from our engineering team"；Cursor Blame 找來源；task description 故意短；每幾個月更新；online 抓到 "where the agent's output looks correct to a grader but feels worse to a developer using the product"；"models like Haiku can match or exceed GPT-5"（部分情況）
  - Epoch 把 CursorBench 4.0 評為 Not enough info（不公開）
- ✔ Claude Code docs, Test plugins with evals. https://code.claude.com/docs/en/plugin-evals （2026-11-03 查，需 v2.1.269+）
  - `claude plugin eval init`、`claude plugin eval .`；每 case 預設跑 3 次；no-plugin baseline、Δ；隔離；grader 六種 regex/tool_used/tool_order/file_exists/llm/baseline；mock MCP；exit code；pin model；範例輸出 first-case 1.00 0.33 +0.67 6 $0.41
