## GitHub Copilot production trace
- Banruo Liu、Haoran Qiu、Íñigo Goiri、Rodrigo Fonseca、Ricardo Bianchini、Esha Choukse（UIUC、Microsoft Azure Research），"Agentic Coding in the Wild: Characterizing GitHub Copilot at Production Scale"。文件沒有日期與 venue；trace 是 2026 年 6 月第一週，參考文獻最新存取日 2026-07-09；URL 路徑 2026/08。
- https://www.microsoft.com/en-us/research/wp-content/uploads/2026/08/ghcp_traces-6.pdf
- Table 3：13.5M sessions、95.1M turns、3.2M users、760.5M LLM calls、774.7M tool calls、44.9T prompt tokens、39.3B completion tokens。只取樣 US region。
- Table 2：calls per interaction：chat 1；coding agent "15 (median), 40+ (mean)"。Autonomy "Agent-driven (87% LLM calls)"。
- Table 4：per session LLM calls median 15、mean 40.6；tool invocations median 13、mean 43.6。
- §5.1：completion median 247，prompt median 68K；chat 的 750／105 來自先前的 production 研究（ModServe、DynamoLLM）。median input:output > 275:1。
- 摘要：KV cache hit rate averaging 90% within a turn, falling to 55% across turn boundaries。§5.4：after a model switch, average 8%。
- §9.1／Table 8：more than 90% of idle intervals intra-turn，median 5.8 s（container）、1.2 s（KV cache），P95 37 s（KV）；cross-turn 8–9%，median 243 s、172 s，P95 5,424 s、4,500 s。Median user idle 1,512 s（25.2 min）。
- §9.3："Within a turn, the session's KV cache should be retained in GPU memory…"；Takeaway 15：turn boundaries are a natural trigger for KV-cache offloading。
- 引言："Tool failures happen in 9% of turns and trigger autonomous retry loops with growing context windows, amplifying compute by up to 4×."
- §11："Without prompt/response content, we cannot correlate infrastructure efficiency with task completion quality."

## TraceLab
- Kan Zhu、Mathew Jacob、Chenxi Ma、Yi Pan、Stephanie Wang、Arvind Krishnamurthy、Baris Kasikci，arXiv 2606.30560，2026-06-29。https://arxiv.org/abs/2606.30560
- 約 4,265 sessions（Claude Code 2,676、Codex 1,589）、357,161 LLM steps、432,510 tool calls；43 developers、約 8 個月。作者自己的日常研究工作流："our trace is drawn from our own day-to-day use"。
- §4.4：human thinking 92.3%、LLM generation 3.3%、tool execution 4.8%（human = gap from previous event to next user message）。每段空檔上限 1 h：64.3%、14.5%、21.2%。
- §6.2：positive tool latency median 0.3 s；average 16.8 s；Claude：> 1 min 的 call 4.9%、佔 92% tool time。
- Table 3：99.60% Claude steps grow context；平均 +1,719 token。
- Table 8：Claude prefix P50 126,180、append 857、output 252。
- Table 11：prefix cache hit 95.7%。
- §4.3：cost shares prefix 59.5%、append 29.2%、output 11.2%；session avg $9.70、median $0.61。
- §7.4：eviction 1 min → 85.4%、R 0.74；5 min → ~94%、R ≈ 1.9；1 h → 98.6%、R 5.07。R = suspended requests' KV storage ÷ active decoding requests' KV storage。

- 設定：Qwen3.6-27B、Gemma4-31B，兩張 H100 NVL，vLLM。Benchmark，不是 production。
- Table II Terminal-Bench 2.0：max concurrency 15／20／25；prefix-cache hit 98.85／16.78／19.21；gen throughput tok/s/req 30.08／16.96／10.30；prefill time 0.51 s／2.24 s／3.46 s。
- Table II DABStep：5／10／15；98.53／25.17／26.60；34.13／22.21／14.82。
- "decode accounts for 91.0–98.6% of LLM time"。"extra prefill tokens slow decode ... reducing average generation throughput by up to 66%"。
