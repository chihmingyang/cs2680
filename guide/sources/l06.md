# L6 外部事實來源（查詢日 2026-11-03）

## 可靠性

- Zhao, Li, Li, Zhao, Barr, Sarro, Ye（UCL、南京大學），Failure as a Process: An Anatomy of CLI Coding Agent Trajectories，arXiv 2607.09510，2026-07。https://arxiv.org/pdf/2607.09510
  - Terminal-Bench；3 scaffold（MiniSWE、OpenHands、Terminus2）× 7 model = 21 系統；1,794 條（1,184 失敗、610 成功）；Claude Opus 4.6 起草標註，人工確認。
  - "71% of successful trajectories encounter at least one error before eventually succeeding."
  - "with a median onset of just 7 execution steps"（decisive error）；"do not become unrecoverable until around step 12"；"the median first observable failure occurs at approximately step 16"；"failed runs contain a median of 27 execution steps (mean 42)"
  - "92% of successful trajectories respond to at least one error signal"，"compared with only 37% of failed trajectories"
  - "26% of failed trajectories fabricate success, and it begins right at the point of lock-in."
  - "Successful recoveries are much shorter than failed ones (median 5 vs. 12 execution steps)."
  - "only 18% of failed trajectories terminate shortly after the error is empirically unrecoverable."
  - Epistemic 57.9%、competence 32.8%、false premises 30.7%。
  - Case study：step 2 cd 靜默失敗，step 6 lock-in，step 23 才看到 not a git repository。
  - 限制："observational rather than causal"；"a controlled snapshot of three scaffolds and seven frontier models"。
- Snorkel AI（Ramya Ramakrishnan），Coding agents don't need to be perfect, they need to recover，2026-02-13。https://snorkel.ai/blog/coding-agents-dont-need-to-be-perfect-they-need-to-recover/
  - 1,805 runs，99 tasks，8 models。每題錯誤數 passed 2.09、failed 2.71；recovery 95.0% vs 73.5%。單一公司的 benchmark。
- Letta，Recovery-Bench，2025-08-27。https://letta.com/blog/recovery-bench
  - Terminal-Bench 平均 26.3%；Recovery-Bench 平均 11.2%，相對下降 57%。環境 + 完整歷史最差。
- Rabanser, Kapoor, Kirgis, Liu, Utpala, Narayanan（Princeton），Towards a Science of AI Agent Reliability，arXiv 2602.16666，2026-02-18。https://arxiv.org/abs/2602.16666v1
  - 15 個 model、2 個 benchmark；能力進步帶來的可靠性進步很小。
- Zhong, Raghunathan（CMU）, Carlini（Anthropic），ImpossibleBench，arXiv 2510.20270，2025-10-23。https://arxiv.org/abs/2510.20270
  - GPT-5：Oneoff-SWEbench 76%；Conflicting-SWEbench 54%。Claude Opus 4.1：Conflicting-SWEbench 50%。o3：49%。
  - 四種作弊：改測試、overload 比較運算子、記錄額外狀態、special-case。Claude 多半改測試（79% 以上）。
  - 緩解：hide tests 接近 0 但傷正常表現；read-only 擋改測試，擋不住 special-case；abort option：GPT-5 54→9%，o3 49→12%，Opus 4.1 效果小得多。
- Justin Young（Anthropic），Effective harnesses for long-running agents，2025-11-26。https://anthropic.com/engineering/effective-harnesses-for-long-running-agents
  - Initializer + coding agent；progress file；feature list JSON，全部從 failing 開始，只能改 passes；git commit；一次一個 feature；端對端測試。"It is unacceptable to remove or edit tests"。
- Prithvi Rajasekaran（Anthropic），Harness design for long-running application development，2026-03-24。https://anthropic.com/engineering/harness-design-long-running-apps
  - "agents reliably skew positive when grading their own work."；"Separating the agent doing the work from the agent judging it proves to be a strong lever"；QA 三輪 $3.24 + $3.09 + $4.06 = $10.39，總計 $124.70（8.3%，本文計算）；"every component in a harness encodes an assumption about what the model can't do on its own"。
- The Register，Replit makes vibe-y promise，2025-07-22。https://www.theregister.com/2025/07/22/replit_saastr_response/
  - Lemkin 的說法：刪了 production DB、無視 code freeze。CEO：Unacceptable；dev/prod 自動分離。單一案例，當事人說法。

## Memory

- Zhu 等，SWE-ContextBench，arXiv 2602.08316，2026-02（v3 2026-05-06）。https://arxiv.org/html/2602.08316
  - Lite，Claude Sonnet 4.5，99 related tasks：No-Context 26.26% / $0.79；Oracle Summary 34.34% / $0.85；Free Summary 22.22% / $0.91；Free Context 26.26% / $0.98；Oracle Context 27.27% / $0.77。Self-Determine match rate 36.36%。"unfiltered or incorrectly selected context provides limited or negative benefits"。
- Gloaguen, Mündler-Sasahara, Müller, Raychev, Vechev（ETH 等），Evaluating AGENTS.md，arXiv 2602.11988，2026-02-12。https://arxiv.org/abs/2602.11988
  - 一般不提高成功率；推論成本平均增加 20% 以上；repository overview 沒幫助；適合寫非標準的做法。
- Letta，Benchmarking AI Agent Memory: Is a Filesystem All You Need?，2025-08-12。https://www.letta.com/blog/benchmarking-ai-agent-memory
  - GPT-4o mini，檔案 + grep、search_files、open、close；LoCoMo 74.0%；Mem0 自報 graph 版 68.5%；作者說 Mem0 的結果 controversial、LoCoMo 比較像 retrieval benchmark。
- Claude Code 文件（2026-11 查）：https://code.claude.com/docs/en/memory、/checkpointing、/cli-reference、/sub-agents、/env-vars、/hooks-guide
- Claude Platform 文件（2026-11 查）：https://platform.claude.com/docs/en/managed-agents/memory、/dreams
- Mem0 文件（2026-11 查）：https://docs.mem0.ai/core-concepts/memory-operations/add，ADD-only；https://docs.mem0.ai/migration/platform-v2-to-v3，"ADD only: nothing is overwritten or deleted"，自報 LoCoMo 91.6（原 71.4）。

## 記憶中毒

- Dong 等，Memory Injection Attacks on LLM Agents via Query-Only Interaction（MINJA），arXiv 2503.03704，2025-03（v5 2026-02-12）。https://arxiv.org/html/2503.03704v5
  - 平均 ISR 98.2%、ASR 76.8%；前提：多使用者共用 memory bank。MIMIC-III 上 benign queries 由 25 到 100，ASR 68.9%→31.1%。Prompt 偵測：targeted prompt 在 MIMIC-III 131/135，RAP 0/135。
- Sunil 等（UMass），Memory Poisoning Attack and Defense on Memory Based LLM-Agents，arXiv 2601.05504，2026-01-09。https://arxiv.org/html/2601.05504v1
  - 空記憶 ASR 62%、ISR 100%；有相關初始記憶 ASR 6.67%、ISR 26.67%（GPT-4o-mini）。Sanitization 在 Gemini-2.0-Flash 把 54 筆惡意查詢以滿分信任存入：confidence filter 不是 security filter。
- Royce Lu、Jay Chen（Unit 42），2025-10-09。https://unit42.paloaltonetworks.com/indirect-prompt-injection-poisons-ai-longterm-memory/
  - Bedrock Agents PoC；Nova Premier v1；沒開 Guardrails；隱藏指令 → summarization → memory（可保留到 365 天）→ 之後的 session 外傳訂單。"this is not a vulnerability in the Amazon Bedrock platform"。
- Microsoft Defender Security Research Team（Noam Kochavi），2026-02-10。https://www.microsoft.com/en-us/security/blog/2026/02/10/ai-recommendation-poisoning/
  - 60 天，email 流量裡的 URL，50 個例子，31 家公司，14 個產業。effectiveness "varies by platform and has changed over time"。未報告持續率。
- Idan Habler、Amy Chang（Cisco），2026-04-01。https://blogs.cisco.com/ai/identifying-and-remediating-a-persistent-memory-compromise-in-claude-code
  - npm postinstall → 覆寫 MEMORY.md 與 hooks；"as of Claude Code v2.1.50, Anthropic has included a mitigation that removes user memories from the system prompt"；Anthropic：本機使用者視為完全信任。
- Idan Habler（OWASP ASI06 lead），2026-05-13。https://genai.owasp.org/2026/05/13/memory-is-a-feature-it-is-also-an-attack-surface/
