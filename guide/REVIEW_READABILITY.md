# 可讀性審查（Readability review）

2026-11-06 晚上加 R9 推理、R10 日常詞當術語、「你知道不算」鐵律：pilot 放行的 L6 第 2 章 ¶6，James 評好理解性 5 分，原因是審查者用自己的 shell 知識補了文章沒寫的機制，而推理缺一步只算 R7 的 NIT。2026-11-06 定；同日在 L6 跑第一次 pilot：三個審查者（tldr＋第 1–5 章、第 6–9 章、第 10 章）共 53 BLOCK、11 NIT。扣掉兩類誤報——半頁 pack 造成的 R3（前幾章解釋過的名詞）約 15 個、pack 沒印 code 內容造成的 R2 3 個——真的要修的約 35 個，全部修完，第二輪另開審查者只審這些定位。兩類誤報已修在工具與 skill 裡（整頁 pack、`codeN 內容`）。起因：L6 第 2 章的一格「Anthropic（2026-03）：穩定偏正面。單一公司的經驗」James 看不懂。七個腳本都過，因為它們檢查結構和版面，沒有一個步驟是「一個沒寫過這頁的人讀一遍」。這份文件定義那一步。做法照 code review：reviewer 不是 author、只看 diff、對照 checklist、blocker 修完才 merge、每個 incident 變成一條 checklist 項。流程見 `WORKFLOW.md` I，操作見 `.claude/skills/readability-review/SKILL.md`。

## 原則

1. **審查者不是作者。** 審查在一個全新的 session（subagent）裡做，它沒看過寫作過程。
2. **審查者只看讀者看得到的東西，但要看整頁。** 給它 `tools/review_pack.py` 的輸出和這份 checklist。不給 slides、`notes/`、`guide/sources/`、`V7_DECISIONS.md`，因為讀者也沒有這些。分給多個審查者時，每個都拿整頁，只審指定的章；否則 R3 會把前幾章解釋過的名詞全標成沒解釋。
3. **重述，不評分。** 審查者對每個單位寫出它自己理解到的意思。它不能回答「看得懂」；它要回答「我讀到的是……」。重述錯了或寫不出來，就是 blocker。原因：讓 model 評「好不好」會穩定偏正面（L6 第 2 章自己講的）。
4. **只審改過的章。** `review_pack.py --since <ref>` 只印文字有變的章。新寫一堂就是全部。
5. **Blocker 清零才 push。** NIT 記下，不擋。最多兩輪：第一輪全審，第二輪只審被標過的單位。兩輪後還有 blocker，留給 James 決定，不要第三輪。
6. **讀者是誰。** 軟體工程師，沒用過 Claude Code，沒讀過其他講次，只讀這一頁，從頭讀到尾。這一頁前面出現過並解釋過的名詞算他知道；別堂解釋過的不算。

## 審查者的一條鐵律：你知道不算，文章寫了才算

審查者的 persona 是軟體工程師，熟 shell、git。這會讓它自己補上文章沒寫的機制（`cd` 失敗為什麼輸出是空的），然後放行。L6 第 2 章 ¶6 就是這樣漏掉的（2026-11-06 晚上 James 評「好理解性 5 分」，審查者第一輪 PASS）。所以每個單位要多問一句：**這段的因果，是文章寫出來的，還是我自己補的？** 自己補的就是 BLOCK。

## Checklist：每個單位各問一次

R1–R6、R9、R10 不過是 BLOCK；R7、R8、R11 是 NIT。單位 = `review_pack.py` 印出來的一行：一段正文、一個清單項、一個表格格子（帶欄名與列名）、一個圖說、一張圖的內容描述、一個收合註的標題。程式碼和指令不審，只審它們的說明。

| 編號 | 問題 | 不過的樣子 | 嚴重度 |
|---|---|---|---|
| R1 重述 | 你能不能用自己的話把這個單位的意思說一次？ | 說不出來；或說出來的和字面能有兩種讀法 | BLOCK |
| R2 主詞 | 這句話在講誰、對誰？「它」「這個」「偏正面」「會過時」指得出對象嗎？ | 述語沒有主詞；代名詞要回頭找兩段以上 | BLOCK |
| R3 名詞 | 這個名詞在這一頁前面出現過並且解釋過嗎？ | 第一次出現就拿來用；只在別堂解釋過 | BLOCK（第一次出現）／NIT（之後再出現） |
| R4 欄名 | 表格格子回答了它那一欄的欄名嗎？欄名是「為什麼」，格子就要有機制；欄名是「換成」，格子就要是做法。 | 格子只有出處、只有數字、只有名詞 | BLOCK |
| R5 引用 | 寫了出處（作者、公司、年月）的地方，有沒有說它量到什麼、結論是什麼？ | 只有「Anthropic（2026-03）」加一個片語 | BLOCK |
| R6 保留語 | 「單一公司」「不是對照實驗」「數字會變」這類保留語，讀者看得出它是在替前一句打折，而不是第二個原因或第二件事嗎？ | 保留語用句號另起一句、和原因並列 | BLOCK |
| R7 接續 | 這個單位和前一個單位接得上嗎？換主題有沒有一句過渡？ | 前一段講 A，這一段突然講 B，中間沒有「所以」「但是」「另一個」 | NIT |
| R9 推理 | 「所以」「因此」「最划算」「關鍵是」後面的結論，前面有沒有寫出推出它的那一步？ | 案例講「第 2 步錯、第 23 步才發現」，結論是「檢查放前面」，中間少了「為什麼放前面划算」 | BLOCK |
| R10 日常詞當術語 | 一個看起來是日常中文的詞，其實是論文或課程的分類名（錯的前提、鎖死、歸納），有沒有一句話說它指什麼？ | 「最大的起因是錯的前提」——讀者以為自己懂，其實對不回案例 | BLOCK |
| R8 圖文 | 圖說和圖的內容描述說的是同一件事嗎？圖說有先問題再結論嗎？ | 圖說的名字和圖裡的標籤對不上 | NIT |
| R11 來回對照 | 要看出這個單位的結論，你有沒有要在幾列數字之間、或圖和段落之間來回對照，自己比大小、算差距？ | 結論說「越來越少」「最划算」，要自己比五列數字才看得出來；段落列了六個數字，要回頭對圖才知道哪個是哪個 | NIT |

不在 checklist 裡的意見（句子太長、用詞喜好、排版）不要寫。James 不偏好短句，為了短句切斷語氣反而更難讀（`STYLE_ARTICLE.md` 第 5 節）。

## 審查報告的格式

```
# 可讀性審查：l06.html　2026-11-06　審了 3 章 110 個單位
BLOCK 4　NIT 6

BLOCK [#i2 表2 列2 ‹為什麼抓不到›]
  我讀到的：Anthropic 在 2026 年 3 月……偏向正面？不知道誰偏向什麼、對什麼偏。
  R2 「偏正面」沒有主詞和對象。
  R4 欄名是「為什麼抓不到」，格子只有出處，沒有機制。
  R6 「單一公司的經驗」用句號另起，讀起來像第二個原因。

NIT [#i2 ¶3]
  我讀到的：……
  R7 前一段講重試，這一段講檢查，少一句過渡。

最難讀的三處（即使都過也要列，依難度排）：
1. [#i2 表2 列2 ‹為什麼抓不到›] 原因一句
2. …
3. …
```

- 每個單位的報告先寫「我讀到的」，再列不過的編號和一句原因。不建議改法；改法是作者的事。
- 「最難讀的三處」一定要寫，就算零 BLOCK 也要。排名不能全過，pass/fail 可以；這是防審查者偏正面的第二道。
- 報告存在 `notes/review/lXX-YYYYMMDD.md`（不 commit），回覆裡貼 BLOCK 的部分給 James 看。

## 作者怎麼用報告

- 每個 BLOCK 都要修，或寫一句為什麼不修（留在報告旁）。修法照 `rewrite-with-example`：接順句子、補名詞的來歷、表格格子寫成有主詞的完整句，放不下就把主張搬回正文、格子只留標籤。
- R11 的 NIT：審查者只說哪裡要來回對照，不建議改成圖；形式由作者決定。先看 `verify.sh` 的 figure-spots 有沒有列同一處；結論是趨勢、轉折或最佳點，就照 `STYLE_ARTICLE.md` 第 6 節〈數字表換成圖〉改，圖要取代表或段落，不是疊上去（2026-11-07）。
- 保留語的固定寫法：放句尾括號，「（Anthropic 一家的經驗，不是對照實驗）」。不另起一句。
- 引用的固定寫法：出處＋量到什麼，「Anthropic 2026-03 的 harness 實驗：agent 替自己的成果打分時穩定給高分」。
- 修完跑第二輪：`review_pack.py --chapter <被標的章>`，審查者只審上一輪標過的定位。作者加了段落，定位就會移動，所以每個定位後面附上第一輪的「我讀到的」，審查者依內容找到對應的單位（2026-11-06 L9–L11）。
- 新頁已經接到全站（側欄、GitHub 連結、別頁連進來的錨點）之後，修 BLOCK 就地改 `docs/lXX.html`，不要從 `notes/lXX/` 的片段重組：重組會蓋掉接線和其他人的修改（2026-11-06 L9–L11）。

## James 的角色

不讀頁面，讀報告。抽一兩個 BLOCK 到頁面上對一下，看審查者有沒有抓對。抓錯了，改這份 checklist 或 `reviewer-prompt.md`，不是改頁面。

## 每次「看不懂」都回到這裡

James 說看不懂的地方，先問：checklist 哪一條該抓到卻沒抓到？沒有對應的條目就加一條（R9…），有條目但審查者沒抓到就改 `reviewer-prompt.md` 的例子。改完在 `guide/CHANGELOG.md` 的「REVIEW_READABILITY.md」一節最上面記一行。
