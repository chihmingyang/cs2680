James 貼了〈Hit rate 的帳〉的算式、表和結論那一段，說：「你這表我看不懂算數，明明是個易懂的小觀念，就是 cache read 很重要，你加了算數後反而看不懂了。」
這一段要講的只有一件事：cache miss 的單價是 cache hit 的 12.5 倍，所以 miss 的 token 很少也會佔掉帳單的一大塊。原文卻給了四個符號（C、h、r、w）的算式，再給一張 7 列 2 欄的表。表的單位是「全部 cache hit 時的幾倍」，這個基準讀者平常不會用；w 的值（1.25×）不在表裡，讀者沒辦法自己驗算；右邊那一欄（r = 0.05×）是換條件重算，是第二個觀念。
為什麼沒被擋：R18 寫明「表格和圖裡的數字不算」，所以 14 格的表不受它管；四個符號各有一行定義，R3 也過。Checklist 沒有一條問「這個結論需不需要算式和表」。〈精簡〉第 1 點把主線寫成「機制 → 算式 → 一個算例 → 結論」，作者照著給了算式；第 3 點（換條件重算不放第二張表）和第 7 點（本頁前面講過的不再解釋第二次：12.5 倍在第 2 章〈Cache 會過期〉已經算過）該擋下右欄和重新定義，寫作時沒照做。
修法：算式、四項定義、表全部刪掉。正文指回第 2 章的 12.5 倍，換成一張圖：hit rate 95% 時，input token 的量是 95：5，花的錢是 60：40。正文只留「5% 的 token 付了四成的錢」和「每次都 cache miss 比不開 cache 貴 25%」。
