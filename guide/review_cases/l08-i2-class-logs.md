James 貼了「CS2680 全班的 Claude Code session log 裡，每一步送進 model 的 token，兩份作業的中位數分別是 208K 和 301K。」問：「我們沒有上 CS2680 的正課，最終目標是根據第一性原理掌握 agent 或 inference 的知識，一開始只是透過 slides 建立骨架，這句話對我們有學習的意義嗎？」接著問為什麼會發生、下次怎麼避免。
為什麼寫進去：寫 v7 時從 slides 吸收證據，講者用自己學生的 log 當佐證，對修課學生有意義（他們寫過那兩份作業），對我們的讀者沒有。查證流程只問「數字有沒有出處」，這個數字有出處，看起來很紮實；精簡的〈佐證〉規則又說「只留讀者會帶走的那個數字」，作者把它當成了那個數字。
為什麼審查沒擋：這句完全讀得懂。Checklist 只問讀者讀不讀得懂，沒有一條問讀者帶不帶得走；審查者的人設也沒寫「沒上過這門課」。這個事件加了 R19 和人設那一行，`check_article.py` 加了「全班」「兩份作業」「Assignment N」「同學」的 warn。
修法：改寫成推得出它的機制（固定開頭加上每一步新進來的內容，走幾十步就到幾十萬 token），加一個讀者會算的例子（context 200K、新進來 2K、output 0.4K → 100、1、0.2）。
