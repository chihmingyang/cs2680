怎麼讀

Part I 的建議順序是 L2 → L4 → L3 → L5，不照編號。L2 和 L3 先用到 context 的代價、subagent 這些詞，L4 才解釋它們；先讀 L4，讀 L3 就不用往後翻。L5 要在 L3 之後讀。

  1. 先讀第 5 段「問題討論」的基礎題，每堂最多 5 題。它們依 slide 順序排列，答案都在 slides 裡。
  2. 帶著問題，自己一頁一頁看完 slides。看到對應的頁，把答案記下來；看完展開「參考答案與重點複習」對照。它先直接回答，再把這一題的觀念整理成一份複習筆記，有些附圖；讀書會後也可以只看這裡複習。卡住的地方、跟參考答案不同的點，按題目下面的「到 GitHub 討論這一題」，留在那一題的討論串。
  3. 再讀文章，或是直接從文章開始也可以。「先看這裡」和架構圖給你整堂的全貌，核心觀念是主體，一章一章由淺入深，名詞在第一次出現的地方就有解釋；「觀念補充」是查閱用的短版。超出 slide 的推論放在對應章節的「本文延伸」裡，預設收合（L4 起；其他講次暫時還有獨立的「延伸思考」段，所以問題討論在 L4 是第 4 段，其他講次是第 5 段）。
  4. 讀書會前：切到進階題，每堂最多 3 題。不用先寫在 GitHub，挑一題想一想就好。每個回答要點下面有一行提示；不知道怎麼開頭，就展開「作答範本」，照著填空。主持人可以按「複製進階題」把題目貼到群組提醒大家。
  5. 讀書會上：打開這一堂的討論串（講次頁第 7 段有連結）。先掃基礎題的留言，把共同卡住的地方挑出來；再一題一題討論進階題；最後回到講次頁展開「參考觀點與追問」。
  6. 想動手時，照「動手試試」做。裡面有可以照打的設定檔、指令或小練習。
  7. 要分工導讀時，用每一堂最後的「延伸閱讀」。教授指定的 readings 都整理在那裡：每篇有建議等級、一句定位和「導讀」切入點，一人認領一篇就能開場。標「必讀」的每一篇另附一段摘要，3 分鐘讀完它的主張、數字、和 slides 重疊的部分，以及原文哪幾節值得看；時間不夠時先讀摘要。

留下你的想法

這不是作業，也不打分數。它是把大家的思考留下來的方法。討論放在這個站台的 GitHub repo 的 Issues：每一堂一串，放那堂的基礎題。看完 slides 後，把基礎題的答案寫成一則留言，用 Q1 到 Q5 當小標；要補充就編輯自己那一則。進階題不用先寫，讀書會當天一起討論。回應別人，按那一則「⋯」裡的 Quote reply，或寫 @對方的帳號。建議先寫自己的，再看別人的。留言要有 GitHub 帳號，看討論不用。討論是公開的，任何人都看得到內容和留言者的帳號。

這份筆記的寫法

文字約 75% 遵守 ASD-STE100（Simplified Technical English）的原則。比喻和因果說明保留彈性。

一句一件事

每句只講一個概念。描述句控制在 40 字以內。

主動語態

✓ harness 執行 tool call。

✗ tool call 被 harness 執行。

術語保留英文

context window、harness、prefix cache 等標準術語不硬翻。

  • 文章不逐頁重講 slides。它整理架構、補背景、做延伸，並附討論題。
  • 「延伸思考」是本文的推論，不是 slides 的內容。每篇都有標示。
  • 基礎題只問 slides 講了什麼；進階題問你會怎麼做。兩者都維持通用，不綁定特定公司或專案。估算題的參考答案附完整算式。
  • 基礎題的參考答案寫成重點複習：答案、重點拆解、背景補充、常見誤解，最後是帶得走的幾點。「答案」與「重點拆解」以 slides 為準並標頁碼；超出 slides 的內容放在「背景補充」。
  • Claude Code 的設定檔與指令已對照 2026 年 10 月的官方文件。
  • 「延伸閱讀」整理自課程網站的官方 readings 清單（cs2680.com/readings）。必讀等級、時間估計與導讀切入點是本站的編輯建議，不是課程要求。「必讀」的摘要用自己的話改寫原文，數字以原文為準；原文連結在每篇標題上。
  • 「閱讀」時間只算不展開時看得到的文字；講次頁另列「全部展開」的時間，包含參考答案、重點複習與深入區塊。
  • 本站不轉載 slides 的圖片。頁碼一律是 PDF 檢視器的頁數，不是 slide 右下角的編號；頁碼連結會開到官方 PDF 的那一頁。
  • 「已讀」標記只存在你自己的瀏覽器。討論放在 GitHub Issues，是公開的。
