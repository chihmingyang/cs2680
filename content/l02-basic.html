  1. p.6–10 · Agent loop

    你輸入一個 prompt 之後，Claude Code 重複做哪三件事？重複到什麼時候才停？Model 和 harness 各負責哪一部分？

    參考答案

    三件事：收集 context、產生下一個 action、執行 tool。每一步的輸入是上一步的結果，直到 model 判斷任務完成。

    Model 只輸出文字，決定下一步，例如提議 Bash("pytest")。Harness（Claude Code 這個程式）組 context、檢查權限、呼叫 tool，再把結果放回 context。p.10 的例子有 5 次 tool 執行、6 次 inference。

  2. p.7–8 · Context 的起點

    你還沒打第一個字，context 裡已經有哪些東西？Claude Code 為什麼不把整個 repo 送給 model，它怎麼拿到需要的程式碼？

    參考答案

    已經有 10,000 個以上的 token：系統指令、專案資訊、CLAUDE.md 與 memory、tool 定義，以及 skill 與 MCP 的名稱和描述。Skill 和 MCP 的完整內容要等 model 決定用時才載入（progressive disclosure）。

    Repo 可能有幾千個檔案，遠大於 context window。Repo 留在磁碟上，model 用 Grep、Read 這類 tool 按需取一小片。所以 agent 只知道它讀過的部分。

  3. p.11 · 權限

    權限檢查發生在哪兩個步驟之間？四種權限模式差在哪裡？Slide 建議什麼情況才用 bypass？

    參考答案

    在「model 提議」和「harness 執行」之間。Tool call 只是提案，要先通過檢查，結果是 allowed、ask 或 denied。

    Manual 每個動作都問；Accept Edits 自動同意檔案編輯，其他仍問；Bypass 全部放行；Auto 由一個小 model 判斷。Bypass 在 model 判斷錯誤時沒有任何防線，所以只在可丟棄的環境（container、VM）裡用。

  4. p.12 · Compaction

    Context 快滿時會發生什麼事？這個動作會丟掉什麼？哪個檔案在這之後會重新載入，這對你寫規則有什麼意義？

    參考答案

    Claude Code 把舊的過程摘要起來，這叫 compaction。它是有損的，摘要會丟掉細節，包括你在對話裡講過的規則。

    CLAUDE.md 在 compaction 後會重新載入。所以重要的規則要寫進 CLAUDE.md，不要只在對話裡說一次。

  5. p.16–19 · 兩種記憶

    Agent 的記憶分哪兩種？CLAUDE.md 和 auto memory 各由誰寫、適合放什麼？它們能不能「強制」agent 做某件事？

    參考答案

    Context 是 working memory，session 結束就消失；persistent memory 存在檔案裡，下個 session 再載入。LLM 本身每次呼叫都從零開始。

    CLAUDE.md 由你寫，放指令、硬規則、難推得的事實。Auto memory 由 Claude 自己寫，放你的偏好、你給的糾正、專案背景。兩者都只是 context，model 可能沒照做；要一定擋下，用 hook。

  6. p.20–22 · CLAUDE.md 的層級

    CLAUDE.md 有哪四個層級？它們互相覆蓋，還是全部串接？CLAUDE.md 太長時該怎麼拆，paths: 有什麼作用？

    參考答案

    Managed policy（組織）、user（~/.claude/CLAUDE.md）、project（./CLAUDE.md）、local（./CLAUDE.local.md）。它們不互相覆蓋，全部串接進 context；範圍最大的先載入，離你最近的最後讀。

    太長時拆到 .claude/rules/，一個主題一個檔。加上 paths: 的 rule，只在 Claude 讀寫符合條件的檔案時才載入；沒有 paths: 的每個 session 都載入。

  7. p.30–31、p.38 · 四種擴充機制

    Skill、MCP、hook、plugin 各解決什麼問題？四種裡哪一種不需要 model「決定使用」就會執行？為什麼這件事重要？

    參考答案

    Skill 放做事的程序與知識；MCP 連到外部資料與動作；hook 在生命週期事件上自動執行；plugin 負責打包與發佈。

    只有 hook 綁在事件上，不需要 model 同意。Skill 和 MCP 都要等 model 決定使用才生效。所以必須強制的規則要用 hook，例如 PreToolUse 擋下某個指令。

  8. p.42 · 設計練習

    「每次編輯後自動格式化」「從 Jira 讀一張 issue」「禁止寫入 production」各該用哪一種機制？先自己判斷，再看 slide 的答案。

    參考答案

    自動格式化用 hook：綁在「編輯完成」這個事件，每次都要發生。讀 Jira 用 MCP：要碰外部系統。禁止寫入 production 用 hook 或 policy：必須強制，不能靠 model 記得。

    判斷順序：要強制嗎？用 hook。要碰外部嗎？用 MCP。要分享嗎？用 plugin。其餘是程序與知識，用 skill。
