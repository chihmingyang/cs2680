你要替一篇教學文章的幾節出 unit 題（每一節讀完就做的小測）。題目會放在頁面上給讀者做，也會當 regression test：文章被改壞時，題目要轉紅。

## 先讀

1. `guide/QUIZ.md` 的〈出題規則〉和〈觀念涵蓋〉兩節，用 Read 讀，其他節不用讀。下面是摘要，兩者衝突時以 QUIZ.md 為準。
2. 範例：L6 已經做完的兩節，看格式和寫法：
   ```bash
   cd /home/claude/cs2680
   python3 -I -c 'import json,re; s=open("docs/l06.html",encoding="utf-8").read(); q=json.loads(re.search(r"id=\"quiz\">(.*?)</script>",s,re.S).group(1)); print(json.dumps([u for u in q["unit"] if u["ks"] in ("k2","k4")],ensure_ascii=False,indent=1))'
   ```
   範例裡的 `closed_ok` 是閉卷測試之後才加的，你不要寫。
3. 你負責的節的文字（spec 包）和觀念清單（points），路徑在這份 brief 最後。

## 規則

1. **觀念清單是 spec。** 每個觀念至少要有一題測到。每題的 `covers` 寫它測哪幾個觀念，而且只能寫自己這一節的。答對這題一定要懂那個觀念才算 cover；題目順帶提到的不算。
2. **題數。** 每一節至少一題。重點節（標題有「（重點）」）至少 4 題，其中至少 2 題選擇、1 題應用，從不同角度問：數字、反過來算、因果、常見的誤解。不要同一題換句話說。
3. **選擇題（`kind: choice`）：**
   - 預設 3 個選項，剛好一個 `"ok": true`。寫得出 3 種真的誤解時才用 4 個。
   - 錯的選項每個都要寫 `why`：選它的人錯在哪，用文章的內容和數字說明。
   - 正確選項和錯誤選項要一樣長、一樣具體、用同樣的句型。正確選項最長，閉卷挑最長的就會對。
   - 錯的選項要說得通，最好是文章要破除的那個直覺。不要寫太絕對、離題、或違反因果，一眼就能刪的選項。
   - 選擇題問文章量到什麼、主張什麼，尤其是常識和文章結論相反的地方。不要出題幹給齊數字、會算就答得出來的題，那種題放到應用題。
   - `key` 是答對之後顯示的解說，一兩句，帶出文章的數字。
4. **應用題（`kind: apply`）：** 換數字或換情境，文章裡沒有現成的答案，只能用這一節講的機制推出來。`key` 一個要點一句，數字寫出來（用 `python3 -c` 算過再寫），每個要點要能單獨判斷對錯。要點只寫文章寫了的東西，也不要要求題目沒問的東西。
5. **同一節的題會一起出現，不能互相給答案。** 一題的題幹或選項不能寫出另一題的答案。兩題其實在考同一件事時，把後一題改成應用題，或兩題併成一題（`covers` 合併）。
6. **一題只問一件事。** 一題問了好幾件事的，拆成好幾題。
7. **題目從現在的文字出。** 不改 `docs/`，也不出文章沒寫的東西。發現文章本身有問題（前後不一致、少一步），寫在輸出的 `_notes`，不要自己改。
8. **題號** 是節號加小寫字母：`k7a`、`k7b`…

## 輸出

寫成一個 JSON 檔，寫到指定的路徑：

```json
{"unit": [
  {"id": "k7a", "ks": "k7", "kind": "choice", "q": "題目",
   "choices": [{"t": "錯的選項", "why": "錯在哪"}, {"t": "對的選項", "ok": true}, {"t": "錯的選項", "why": "錯在哪"}],
   "key": ["答對後顯示的解說"], "covers": ["k7.1", "k7.3"]},
  {"id": "k7b", "ks": "k7", "kind": "apply", "q": "換情境的題目", "key": ["要點一", "要點二"], "covers": ["k7.2"]}
],
 "_notes": ["文章本身的問題，一條一句；沒有就給空清單"]}
```

寫完自己對一次：你負責的每個觀念 id 都出現在某一題的 `covers` 裡；每個重點節的題數符合第 2 條。
