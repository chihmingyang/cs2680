你要替一篇教學文章列出「每一節教了哪些觀念」。這份清單是題庫的 spec：之後每個觀念都要有一題測它，所以漏列的觀念就不會被測到。你沒看過題目，也不要去猜題目會問什麼。

## 輸入

一份觀念清單包（路徑在這份 prompt 最後）。內容依節分組：每節開頭是 `## kN　標題`，標題後面有「（重點）」的是這一章的主要主張；下面每行是一個單位，寫法是 `[定位] 文字`。定位像 `#i2 ¶1`（第 2 章第 1 段）、`#i2 表1 列2`、`#i2 圖3 內容`、`#i2 code1 內容`。

## 規則

1. **只列這份文字寫了的東西。** 你自己知道、文字沒寫的不列；文字只是暗示、沒有寫出來的也不列。
2. **一個觀念一條，寫成一句完整的話。** 要有主詞，數字要寫出來：寫「通過與失敗的任務修復率是 95.0% 與 73.5%」，不寫「修復率差很多」。讀的人只看這一句，就要知道這個觀念在說什麼。
3. **每條標一種 type：**
   - `claim` 主張：這一節要讀者相信的結論。
   - `mechanism` 機制：為什麼成立、怎麼運作、怎麼算。
   - `condition` 前提：主張要成立，得先有什麼條件。
   - `limit` 限制：例外、代價、做不到的地方、根據有多強（例如是觀察不是實驗、只有一家公司的經驗、數字會變）。
   - `misconception` 誤解：文章明說或明顯要破除的直覺，例如「以為 X，其實 Y」、「不是 A，而是 B」。
4. **後三種最容易漏，要回頭再掃一次。** 每一節先列完主張和機制，再一段一段問：這裡有沒有寫前提？有沒有括號裡的保留語、例外、代價？有沒有「不是…而是…」「常被誤以為」？有就各列一條。這篇文章的上一份題庫只測到 27% 的限制，原因就是清單只列了主張。
5. **一句話有兩半，兩半都要列。** 例如「來源同一等級時才比新舊」有兩件事：要比新舊、只在同一等級之間比。上一次的 mutation test 抓到題目常常只測其中一半，所以分成兩條。
6. **圖、表、程式碼也算。** 表格的一列寫了一個結論，就是一條；程式碼註解寫的行為也是一條。圖說和正文講同一件事，只列一條，`at` 兩個定位都寫。
7. **不列這些：** 轉場句；「第 N 章會講」這類預告；連結的標題；只是舉了一個名字的例子。例子有撐住一個結論時，把結論連同數字一起寫成一條。
8. **條數不要湊。** 重點節多半 8–12 條，其他節多半 3–8 條。但兩個獨立的觀念不要併成一條，沒有東西的節也不要硬擠。每一節至少要有一條。
9. **`at`** 寫支持這一條的單位定位，照包裡方括號的寫法，可以寫好幾個。

## 輸出

只輸出一個 JSON 檔，寫到指定的路徑，不要其他文字：

```json
{"points": {
  "k1": [
    {"id": "k1.1", "type": "claim", "t": "一句話", "at": ["#i1 ¶1"]},
    {"id": "k1.2", "type": "limit", "t": "一句話", "at": ["#i1 ¶3", "#i1 圖1 說明"]}
  ],
  "k2": []
}}
```

`id` 是節號加流水號（`k1.1`、`k1.2`…）。包裡的每一節都要出現在 JSON 裡。
