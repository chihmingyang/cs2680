下面是一批選擇題。另一個 agent 沒有讀過題目出自的文章，閉卷作答，這些題它都答對了，而且說自己有把握。你要判斷每一題它為什麼答得出來。

## 輸入

- `closed.md`：題目和選項，字母和作答時看到的一樣。
- `closedcheck.txt`：只分類「要改的」那一段列出的題。每題後面是作答者自己寫的判斷理由。

兩個檔案的路徑在這份 prompt 最後。

## 五種原因

先看前三種。前三種是題目本身的線索，一定要改題。都不是，才在後兩種之間選。

| 類別 | 意思 | 例子 |
|---|---|---|
| `compute` | 題幹給齊了全部輸入，會算就答得出來 | 題幹給了「每步 95%、50 步」，問全對的機率 |
| `option` | 選項本身是線索：正確選項最長、最具體；或錯的選項一眼就能刪（太絕對、離題、違反因果） | 正確選項有兩個子句、一個數字，錯的選項都只有半句 |
| `leak` | 題幹或選項寫出了答案；或同一批的另一題，題幹或選項寫出了它的答案 | k20b 的選項寫了「記錯比沒記代價高」，就是 k18a 的答案 |
| `knowledge` | 這個領域的常識，懂行的人本來就知道 | 「重試要冪等」 |
| `reasoning` | 從題幹描述的因果或定義就推得出來，不需要文章 | 題幹說「錯誤會往後傳」，問接手失敗的環境成功率會變高還是變低 |

## 輸出

只輸出一個 JSON 物件，寫到指定的路徑，不要其他文字：

```json
{"k3a": {"cat": "option", "why": "一句話：線索是什麼", "fix": "一句話：怎麼改"},
 "k5c": {"cat": "leak", "from": "k5a", "why": "k5a 的題幹寫了答案", "fix": "…"},
 "k9b": {"cat": "knowledge", "why": "一句話：哪個常識"}}
```

- `compute`、`option`、`leak` 要寫 `fix`。
- `leak` 要寫 `from`：答案是從哪一題洩漏的。是題目自己洩漏，就寫自己的題號。
- 只用這兩個檔案判斷，不要讀其他檔案，不要上網查。
