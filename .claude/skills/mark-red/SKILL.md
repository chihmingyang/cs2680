# 標紅字：可讀性審查之後才做的一步

規則在 `guide/STYLE_ARTICLE.md` 6c，流程在 `guide/WORKFLOW.md` I2。這份 skill 是操作步驟。

## 為什麼獨立成一步、而且排在審查之後（2026-11-11 James）

- **審查會改字。** 審查前標的紅字，句子一改寫就落在不存在的話上，或變成半句。L6b 審了四輪，紅字是每一輪順手補的，結果問句被標紅、最重要的做法（歸納另存一份）沒有紅字。
- **紅字要看整章才決定得了。** 它是一條掃讀路徑，名額有限（依章的長度，見 6c），要整章的小標都定了才能分配。寫一段的當下只看得到那一段。
- **順序反過來不花成本。** 審查紀錄的 hash 只算讀者看得到的文字，搬 `<strong>` 不會讓紀錄失效；反過來，審查改字會讓紅字失效。

所以：**寫作和修 BLOCK 的時候不標紅字**（原本有的留著不動），審查記完 `review_status.py mark` 之後才做這一步。

## 1. 過關卡，印掃讀路徑

```bash
cd /home/claude/cs2680
python3 -I tools/red_path.py lXX            # 整頁；只做幾章：red_path.py lXX i2 i3
```

- 印「先做可讀性審查，再標紅字」：那幾章是沒審過、改過或舊規則。先照 `readability-review` 審完，不要用 `--force` 繞過去（`--force` 只給想看現況的時候用）。
- 過了就印每一章的掃讀路徑：`##` 是章名，`■` 是開一段的 `<b>` 小標，`·` 是清單裡的 `<b>`，`→` 是紅字，`?` 是提示。

## 2. 只讀這條路徑，重建論證

不看正文，從上讀到下，問三件事（STYLE_ARTICLE 6c〈紅字是給誰的〉）：

1. **推得回這章的論證嗎？** 每個 `■` 是一個題目，後面的 `→` 要是它的答案（做法、判斷或代價）。`? 小標後面沒有紅字` 是候選，不是一定要補：名額不夠時，先給這章論證少不了的那幾節；查閱性質的小節、只是分類的小節可以沒有。
2. **離開上下文看得懂嗎？** `? 靠上下文才懂` 的那幾處，把範圍拉長到包住主詞或條件。問句、指路句（「先看第 3 章」）不標。
3. **標的是意思嗎？** `? 只有數字` 的拉長到包住數字的含義。`? 重複小標` 的換成那一節的答案。

然後才回正文找句子。優先順序：結論或做法 → 代價、陷阱、誤解 → 數字連同意思。

## 3. 改：只搬 `<strong>`，不改字

- 只加、刪、移 `<strong>` 標籤。**一個字都不改**：改了字，那一章的審查紀錄就變「改過」，要回去重審。
- 好的紅字需要改字才成立（例如句首是「它」）：這一次不標那一句，或標同一節的另一句；把要改的字記進回覆，下次動到那一章時和審查一起做。
- 頁面後段有題庫（`<script type="application/json" id="quiz">`），裡面有和正文一樣的句子。用程式取代時只處理這個標籤之前的部分。
- 數量、長度、位置照 6c：每章約 200 字 1 處，上限 round(字數 ÷ 150)（2026-11-13 James：可以再多一點）；`tldr` 剛好 3；一句最多一處；不放在標題、`figcaption`、表、code、`details.gloss`、動手試試。

## 4. 檢查、push

```bash
python3 -I tools/red_path.py lXX                 # 再讀一次路徑；剩下的 ? 每一條心裡要有理由
python3 -I tools/review_status.py status lXX     # 仍然全部 ok（沒有不小心改到字）
bash tools/verify.sh lXX                         # check_article 的紅字數量與位置沒有 warn
```

照 WORKFLOW D push。回覆 James：小修改只列改了什麼（新加、拿掉、拉長各幾處，各一句理由）；不重貼全文。

## 什麼時候要重做

- 一章的文字改過並重審之後：只重做那一章（`red_path.py lXX i3`）。
- James 在站台上自己標的紅字（commit 訊息「網頁編輯：…」）是他的決定，不搬走；名額因此超過時，拿掉的是原本的，不是他標的。
